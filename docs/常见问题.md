# 常见问题

按「你可能遇到什么」排查。每条都给可直接复制的命令（Windows PowerShell）。

---

## 1. `git push` 被拒绝：`! [rejected] ... (fetch first)`

**原因**：远程有你本地没有的提交（别人先 push 了）。
**解决**：

```powershell
git pull --rebase
git push
```

`--rebase` 会把你的提交「重新接到」最新代码后面，历史更干净。
如果 `git pull` 报冲突，见下面第 2 条。

---

## 2. 冲突了：文件里出现 `<<<<<<<`、`=======`、`>>>>>>>`

**别慌，也千万别删文件重来。** 冲突只是 git 说「这两处我拿不准该留哪个」。

```powershell
git status                 # 列出「both modified」的文件
code 冲突的文件.md          # 用编辑器打开，手动改
```

文件里长这样：

```markdown
<<<<<<< HEAD
我的版本：学习率取 0.01
=======
别人的版本：学习率取 0.1，并加了动量
>>>>>>> origin/main
```

**把三个标记删掉，留下你想要的最终内容**（可以两者融合）：

```markdown
学习率取 0.01，并加了动量项
```

然后：

```powershell
git add 冲突的文件.md
git rebase --continue     # 如果你在用 rebase
# 或者： git commit        （如果你在 merge）
```

> 改不动了想放弃这次 pull：`git rebase --abort` 或 `git merge --abort`，回到 pull 之前的状态。

---

## 3. 我直接在 `main` 上改了，还没提交，怎么办？

把改动搬到新分支（改动不会丢）：

```powershell
git switch -c feat/w03-lab02-zhangsan
git add -A
git commit -m "feat(w03-lab02): ..."
git push -u origin feat/w03-lab02-zhangsan
```

如果**已经提交到本地 main 了**（还没 push）：

```powershell
git switch -c feat/w03-lab02-zhangsan     # 带着提交一起走
git switch main
git reset --hard origin/main              # main 回到和远程一致
```

---

## 4. 提交信息写错了 / 漏加了文件（还没 push）

```powershell
# 漏了文件
git add 漏掉的文件
git commit --amend --no-edit

# 想改提交信息
git commit --amend -m "feat(w03-lab02): 正确的说明"
```

**已经 push 了**就别 amend（会改写历史、影响别人），直接再提交一个 `fix(...)` 即可。

---

## 5. 想撤销最近一次提交

```powershell
git reset --soft HEAD~1     # 撤销提交，改动还在（推荐）
git reset --hard HEAD~1     # 撤销提交，改动一起删掉（危险，确认后再用）
```

已经 push 到共享分支的，**不要 reset**，用 `git revert <commit>` 生成一个反向提交。

---

## 6. 误提交了不该提交的文件

```powershell
git rm --cached 文件名            # 从 git 移除，本地文件保留
git commit -m "chore: 移除误提交的文件"
```

> 注意：这样只是「以后不再跟踪」，**文件还在历史里**。如果是密码、密钥，
> 立刻去对应平台**作废并换新**，只改 git 是没用的。

---

## 7. push 报 `file is 123.45 MB; this exceeds GitHub's file size limit of 100 MB`

大文件不能直接提交。

```powershell
git rm --cached 大文件.zip
```

把 `.zip` 加进 `.gitignore`，文件用 **GitHub Release** 或网盘分享，
在作业 `README.md` 里放链接。如果大文件已经在历史里，需要 `git filter-repo` 清理，
**先问一下管理员**再动手。

---

## 8. 中文文件名显示成 `\346\226\207\344\273\266.md`

```powershell
git config --global core.quotepath false
```

---

## 9. 每次 push 都弹登录窗口

第一次登录时如果没选「记住」，凭据就没存。清理后重新登录：

```powershell
git credential-manager github logout    # 或打开「凭据管理器」删除 git:https://github.com
git push                                 # 会重新弹窗，这次选 Sign in with your browser 并允许记住
```

---

## 10. 我想看看别人到底改了什么

```powershell
git log --oneline --graph -15             # 最近的提交线
git show <提交编号>                        # 某个提交的完整改动
git log -p -- week03/lab02/               # 某份作业的全部改动历史
```

在 GitHub 网页上：仓库 → **Commits**，或者打开 PR → **Files changed**。

---

## 11. 我的分支跟 main 差太多了，想同步一下

```powershell
git switch 我的分支
git fetch origin
git rebase origin/main
```

有冲突就按第 2 条处理。**别用 `git merge main`**，会在你的分支里留一个无意义的合并提交。

---

## 12. 彻底乱了，想回到干净状态

先确认你的东西都 push 了（`git status` 干净，或者已经 push）。然后：

```powershell
git fetch origin
git switch main
git reset --hard origin/main
```

> 这会丢弃所有未提交的改动。确认过再执行。

---

## 13. 跑脚本时报「因为在此系统上禁止运行脚本」

Windows 默认禁止运行未签名的 `.ps1`。**不要为此去改系统安全设置**，用仓库里附带的
`.cmd` 包装器即可：

```powershell
scripts\new-homework.cmd -Week 3 -Id lab02
```

如果非要直接跑 `.ps1`，就带上参数跑（只对这一次生效）：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\new-homework.ps1 -Week 3 -Id lab02
```

---

## 14. 不确定自己该干什么

1. 打开想做的作业文件夹的 `接力记录.md`，看最后一行
2. 看 `README.md` 里的「当前状态」
3. 还是不清楚 → 开一个 Issue 问，别闷着猜
