## 第 3 步：邀请成员

仓库页面 → **Settings** → 左侧 **Collaborators**（有的版本在 "Access" 下）
→ **Add people** → 输入对方的 **GitHub 用户名** 或注册邮箱 → 选 **Write** 权限 → 发送。

对方会收到邮件，**必须点接受** 才生效。可以在 Collaborators 列表里看到
`Pending invite`，变成头像就是接受了。

| 权限 | 能给什么 | 建议 |
|------|----------|------|
| Read | 只能看 | 围观者 |
| **Write** | 能推分支、开 PR | **给所有组员这个** |
| Admin | 还能改设置、删仓库 | 只给自己，最多再给 1 个信任的人 |

**不要给 Admin。** 组员互相之间不需要管理权限。

---

## 第 4 步：保护 `main` 分支（强烈建议）

Settings → **Branches** → **Add branch protection rule** / **Add classic branch protection rule**：

- Branch name pattern: `main`
- ✅ **Require a pull request before merging**
  - ✅ Require approvals：`1`
- ✅ **Do not allow bypassing the above settings**（如果需要自己也受约束）

> 注意：私有仓库的分支保护在部分套餐里不可用。如果找不到这个选项，
> 不影响使用——靠 CONTRIBUTING 里的约定执行即可，只是防不住误操作。

## 第 5 步：自己先跑一遍完整流程（验收）

建 `week01/lab01` 就是给你练手 + 做范例的。建议你亲手走一遍，
熟悉后再教别人：

```powershell
git switch -c docs/setup-demo
# 随便改一点 week01/lab01/接力记录.md
git add -A
git commit -m "docs(w01-lab01): 添加接力记录示例"
git push -u origin docs/setup-demo
```

去 GitHub 点 **Compare & pull request** → 填模板 → Create → **Squash and merge** → Delete branch。

能跑通，说明协作者大概率也能跑通。

## 日常维护（每周 5 分钟）

- [ ] 把合并完的分支删掉（GitHub 上会显示 "branches" 计数，堆积了就是没删）
- [ ] 看有没有 `待接手` 的作业，在群里点一下名
- [ ] 周五把 `main` 打个 tag 存档：`git tag w03-done && git push --tags`（可选，方便回看）
- [ ] 定期确认没有大文件混进来：`git count-objects -vH`（`size-pack` 大于几百 MB 就该查了）

## 如果以后想加人 / 换方式

- **加人**：Settings → Collaborators，随时可加
- **移除人**：同一页面 Remove（对方的本地副本删不掉，所以别往里放敏感信息）
- **想改成公开**：Settings → General → 最下面 Danger Zone → Change visibility
  （公开后任何人都能 Fork，历史也会公开，谨慎）
- **想换组织**：Settings → General → Transfer ownership
